01 — Repository Setup

A Git repository stores a project's files and revision history.

For a new project:

mkdir git-practice
cd git-practice
git init
git status

For an existing GitHub project:

git clone https://github.com/ManopovMuhammadali/Web-programming.git
cd Web-programming
git status
This portfolio already has a GitHub repository. Use the clone commands when working with a fresh copy.

02 — Staging and Commits

Staging selects which changes will be included in the next commit. 

git status
git add index.html
git status
git commit -m "Update portfolio homepage"
git log --oneline -5

A commit creates a snapshot of the staged changes. Meaningful commit messages help explain the project history.

03 — Creating a Feature Branch

A branch lets you work on a feature independently of the main branch. 

git switch main
git pull origin main

git switch -c feature/portfolio-update

git status
git add .
git commit -m "Add portfolio feature"
git push -u origin feature/portfolio-update

04 — Pull Request and Merge

  1. Open your repository on GitHub.
  2. Select the feature branch.
  3. Choose Compare & pull request.
  4. Set main as the base branch.
  5. Review the changed files.
  6. Create the pull request.
  7. Merge it after reviewing the changes.

Update your local main branch:

git switch main
git pull origin main

05 — Push Changes to GitHub

The remote repository stores your project online and allows other people to access it. 

git remote -v
git add .
git commit -m "Complete coursework task"
git push origin main

06 — GitHub Pages Deployment

  1. Open your repository on GitHub.
  2. Go to Settings.
  3. Open Pages.
  4. Choose Deploy from a branch.
  5. Select main as the branch.
  6. Select the root folder.
  7. Save the configuration.
  8. Open the published website.

07 — Custom 404 Page

A 404 page is displayed when a visitor requests a page that does not exist.

GitHub Pages supports a custom error page when a file named 404.html is placed in the repository root.
