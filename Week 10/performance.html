WEEK 10 / PERFORMANCE PROJECT

Website Optimization and Performance Report

This report explores five website performance techniques, their implementation, and the effect they can have on loading speed and user experience.

Testing status: The optimization examples are documented below. Actual Lighthouse measurements must be entered after testing.

01 — Image Optimization

Large images increase page size and can delay the Largest Contentful Paint (LCP). Modern formats such as WebP and AVIF can reduce image file sizes.

Before optimization


<img src="large-image.jpg"
     alt="Web development workspace">

After optimization


<picture>
  <source
    srcset="workspace.avif"
    type="image/avif">

  <source
    srcset="workspace.webp"
    type="image/webp">

  <img
    src="workspace.jpg"
    alt="Web development workspace"
    width="800"
    height="500">
</picture>

The browser selects a supported image format. Width and height reserve the image space and help prevent layout shifts.

02 — Lazy Loading

Images outside the initial viewport do not need to load immediately. Lazy loading delays their download until they approach the visible area.

Before optimization


<img src="gallery-photo.jpg"
     alt="Gallery photo">

After optimization


<img
  src="gallery-photo.webp"
  alt="Gallery photo"
  width="700"
  height="450"
  loading="lazy"
  decoding="async">

Important: do not lazy-load the main hero image if it is the page's Largest Contentful Paint element.

03 — JavaScript Loading Strategy

Normal scripts in the document head can block HTML parsing. The defer attribute allows the browser to continue parsing before executing the script.

Before optimization


<head>
  <script src="app.js"></script>
</head>

After optimization


<head>
  <script src="app.js" defer></script>
</head>

Deferred scripts execute after HTML parsing and before the DOMContentLoaded event.

04 — Font Loading Optimization

External fonts can delay text rendering. Using appropriate font loading hints and font-display can improve the experience.

Before optimization


@font-face {
  font-family: "MyFont";
  src: url("my-font.woff2");
}

After optimization


@font-face {
  font-family: "MyFont";
  src: url("my-font.woff2") format("woff2");
  font-display: swap;
}

The swap value allows fallback text to appear while the custom font loads.

For externally hosted fonts, consider preconnect hints when the external origin is actually used. 


<link rel="preconnect"
      href="https://fonts.googleapis.com">

<link rel="preconnect"
      href="https://fonts.gstatic.com"
      crossorigin>

05 — Minification and Caching

Minification removes unnecessary spaces and comments from CSS and JavaScript files. This reduces the amount of code that needs to be downloaded.

Before optimization


function greetUser(name) {
  // Display a welcome message
  const message = "Hello " + name;

  console.log(message);
}

After optimization


function greetUser(n){const m="Hello "+n;console.log(m)}

Caching allows browsers to reuse downloaded resources instead of requesting every file again. Proper cache headers must be configured by the hosting platform or server.

Example server configuration concept: 


Cache-Control: public, max-age=31536000, immutable

This long-lived policy should only be used for versioned static files whose URLs change when their contents change. It is not automatically configured by adding this text to an HTML page.

06 — Core Web Vitals

Core Web Vitals measure important parts of real-world user experience.

LCP Largest Contentful Paint

How quickly the main content appears.

INP Interaction to Next Paint

How responsive the page feels to interactions.

CLS Cumulative Layout Shift

How much content unexpectedly moves.

08 — Critical Rendering Path Reflection

The Critical Rendering Path describes the browser's process of turning HTML, CSS and JavaScript into pixels on the screen.

The browser parses HTML to build the DOM and CSS to build the CSSOM. These structures are combined to create the render tree. Layout determines element positions and painting displays the result.

Large images, render-blocking resources and unnecessary JavaScript can delay this process. Image optimization, deferred scripts and efficient font loading help reduce unnecessary work during initial page rendering.

Conclusion

Website performance is not only about loading speed. It also includes visual stability and interaction responsiveness. These five optimization techniques can improve the experience when applied correctly. Lighthouse helps identify issues and measure actual changes after optimization.
